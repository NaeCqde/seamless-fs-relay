# seamless-fs-relay の仕様

`sfs`(seamless-fs)のサーバー同士を、お互いにつなぐ Cloudflare Worker。各サーバーが「自分のファイル一覧」を送ると、ほかのサーバーに知らせる。ファイルの中身は通らない(一覧に出るリンクは、そのファイルがあるサーバーを指す)。

## 信用の置き方

| 誰が | できること | できないこと |
|---|---|---|
| サーバー(自分のトークンを持つ) | 自分の一覧の登録・削除 | ほかのサーバーのふり、リレーのふり |
| リレー(秘密鍵を持つ) | サーバーに一覧を送る | トークンの復元(SHA-256 しか持たない) |
| 設定やストレージを読んだ人 | ハッシュと公開鍵が分かる | 登録、リレーの署名 |

- トークンは**サーバーごと**。リレーに置くのはそのハッシュだけ(`SERVERS`)。
- リレーからサーバーへの呼び出しには、リレーだけが作れる署名が付く。サーバーは公開鍵だけを持つ。

## 設定(`wrangler.toml` の `[vars]` と secret)

| 名前 | 内容 |
|---|---|
| `SERVERS` | JSON。`{"https://a.example.com": "<トークンの SHA-256 (小文字16進64桁)>", ...}` |
| `RELAY_PUBLIC_KEY` | リレーの公開鍵(base64url)。サーバーの `.env` にも同じものを書く |
| `RELAY_PRIVATE_KEY` | リレーの秘密鍵(base64url)。**secret**: `wrangler secret put RELAY_PRIVATE_KEY` |
| `KV` | KV の binding。サーバーごとの一覧を `files:<アドレス>` で保存する |

秘密の作り方(`sfs` のサブコマンド):

- `sfs token` → サーバーの `TOKEN`(`.env` に)と、その SHA-256(`SERVERS` に)。
- `sfs keygen` → `RELAY_PRIVATE_KEY`(リレーだけ)と `RELAY_PUBLIC_KEY`(リレーとサーバー全部)。
- `sfs hash`(標準入力のトークン)、または `printf %s "$TOKEN" | shasum -a 256` でもハッシュは出せる。

`SERVERS` が JSON でない・ハッシュが不正・同じトークンが2つ・秘密鍵がない、のときは 500 を返し、何もしない。サーバーを足す・外すときは `SERVERS` を書き換えて deploy する。アドレスは小文字のホスト名、既定のポートなし、末尾の `/` なしに直して比べる(`sfs` の `ORIGIN` も同じ形に直される)。

## サーバー → リレー

`PUT` か `DELETE`(パスは何でもよい)。ヘッダー `Authorization: Bearer <トークン>`。本文は JSON `{"origin": "<自分のアドレス>", "files": [{"parent": "/a/b/", "name": "x.txt", "size": 12}]}`(`DELETE` は `origin` だけ)。

| 結果 | 意味 |
|---|---|
| 200 | 受け付けた |
| 401 | トークンがない、または `SERVERS` のどれのものでもない |
| 403 | トークンの持ち主のアドレスと `origin` が違う(ほかのサーバーのふりはできない) |
| 400 / 413 | 本文が不正 / 500 KB を超える(`files` は 20,000 件まで) |
| 405 | `PUT` と `DELETE` 以外 |

- `?first=true`: 起動時の登録。ほかのサーバーに一覧を知らせ、**この**サーバーに、ほかのサーバーの一覧を送る。それ以外は、前回と一覧が違うときだけほかのサーバーに知らせる。`first=false` は `first` ではない。
- `files` は `parent` `name` `size` だけを残す(並べ替えて保存するので、順番が違うだけでは「変わった」とならない)。`url` と `origin` は捨てる: 登録したサーバーが、ほかのサーバーのページに勝手なリンクを出せないように。名前に `/`・制御文字、`..` を含むものも捨てる。
- 応答を返してから、ほかのサーバーに知らせる(`waitUntil`)。

## リレー → サーバー

`PUT <サーバーのアドレス>/`(一覧: `{"origin": 相手, "files": [...]}`)と `DELETE <サーバーのアドレス>/`(`{"origin": 消えたサーバー}`)。送る先は `SERVERS` のアドレスだけ。リダイレクトは追わない。5秒で打ち切る。

ヘッダー:

- `x-relay-timestamp`: 送った時刻(UNIX 秒)
- `x-relay-signature`: Ed25519 署名(base64url)。署名する文字列は次の5行を `\n` でつないだもの: `sfs-relay v1` / メソッド / 送り先のアドレス / 時刻 / 本文の SHA-256(小文字16進)

サーバーは、公開鍵で署名を確かめ、時刻が±60秒以内であることを見る。送り先のアドレスを署名に含めるので、ほかのサーバー宛ての呼び出しは使い回せない。

答えない(接続できない・時間切れ)サーバーは、一覧から外して、ほかのサーバーに知らせる。エラーを返しただけなら外さない。

## 構成(`src/`)

`index`(受け付けと流れ)、`servers`(`SERVERS`・トークンの照合)、`payload`(本文の検査)、`sign`(署名)、`push`(サーバーへの送信)、`store`(KV)、`crypto`(ハッシュ・比較)。テストは `test/`(`pnpm test`、型は `pnpm check`)。

## 古い版からの移行

通信の方式が変わったので、リレーとすべてのサーバー(`sfs`)を同時に新しくする。

1. `sfs keygen` で鍵を作り、`wrangler secret put RELAY_PRIVATE_KEY`、`RELAY_PUBLIC_KEY` を `wrangler.toml` に。
2. サーバーごとに `sfs token`。`TOKEN` と `RELAY_PUBLIC_KEY` を各サーバーの `.env` に、ハッシュを `SERVERS` に。
3. `wrangler deploy`、サーバーを再起動。
4. 古い版の KV の項目(`origins` と、アドレスそのものの名前の項目)は使わなくなる。`wrangler kv key delete` で消してよい。古い共通の `TOKEN`(`[vars]`)は無効にする。

## 限界

- 署名の時刻だけでは、60秒以内の再送は防げない。再送されても結果は同じ(一覧の入れ替え)なので許している。
- KV は結果整合なので、登録の直後は一覧に反映されないことがある。
- サーバーが通信を暗号化するかは、アドレスが https かどうかによる。トークンも一覧も、http では盗み見られる。
